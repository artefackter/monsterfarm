# Вырасти монстра / Grow a Monster

Текущее состояние проекта на 12 ноября 2026 года. Согласованный Дилер V4 установлен: отдельная большая голова и две руки, пассивная и агрессивная формы. Сохранение в Roblox — версия **243**, без публикации.

## Открыть текущий проект

Откройте `place/GrowAMonster-current.rbxl` в Roblox Studio через **File → Open from File**. Это полная копия сохранённого плейса: скрипты, модели, настройки, импортированные пакеты и сохранённые в ServerStorage резервные копии. Во время подготовки экспорта Play не запускался.

Большая часть мира и интерфейса создаётся игровыми скриптами при запуске. Поэтому почти пустой Workspace в редакторе соответствует устройству этого проекта; сцена не потеряна.

С 17 ноября 2026 года в репозитории лежат только актуальные ассеты. Превью, zip-пакеты, промежуточные файлы, старые версии, референсы и непринятые предложения перенесены в `C:\Roblox\MonsterFarm-archive` с теми же относительными путями (список — в `MOVED.txt` там же); чтобы вернуть что-то, достаточно скопировать обратно.

Локальные черновики и старые итерации вне этого набора остались в исходной рабочей папке. Резервные объекты, уже находившиеся внутри ServerStorage, сохранены в копии плейса и экспортированных данных сервисов.

## Работа через Rojo

Проверено с **Rojo 7.7.1**, Python 3 и Luau compiler. Версия Rojo закреплена в `rokit.toml`; установить инструменты можно через [официальный Rojo](https://github.com/rojo-rbx/rojo/releases/tag/v7.7.1).

Полная сборка из исходников, включая библиотеку моделей и настройки сервисов:

```sh
mkdir -p build
rojo build default.project.json -o build/GrowAMonster.rbxl
```

Для синхронизации **только кода** с уже открытой копией плейса:

```sh
rojo serve sync.project.json
```

Подключите плагин Rojo в Studio. Используйте `sync.project.json` для работы с открытым плейсом: он сохраняет объекты, которыми управляет Studio. `default.project.json` предназначен для полной сборки. [Формат проектов Rojo](https://rojo.space/docs/v7/project-format/).

## Проверки

```sh
python3 tools/verify_export.py
python3 tools/verify_export.py --rojo rojo --luau-compile luau-compile
```

Проверяются целостность экспортного снимка, исходники и классы 121 рабочего скрипта, сборка и соответствие 702 шаблонов ArtLib. Проверка не открывает Studio и не запускает игру. Контрольные суммы фиксируют именно этот снимок; после намеренных изменений кода старые суммы перестанут совпадать.

Для повторного экспорта сохраните новую копию из Studio и выполните:

```sh
python3 tools/export_snapshot.py place/GrowAMonster-current.rbxl --rojo rojo
```

Эта команда обновляет экспортированные скрипты, данные сервисов и `default.project.json`. Выполняйте её в чистой копии репозитория: она предназначена для переноса состояния **из Studio в файлы**. После нового экспорта обновите реестры и контрольные суммы; исходные отчёты относятся к версии 243. [Официальное описание syncback](https://github.com/rojo-rbx/rojo/releases/tag/v7.7.0#syncback).

## Ассеты и сохранения игроков

Исходный Roblox Place ID: `133761867075682`, Universe ID: `10774761288`, владелец ассетов: `11935827585`. Модель Дилера V4: `126374725084007`.

Файл плейса хранит ссылки на загруженные Roblox Mesh/Image/Audio-ассеты. Для загрузки геометрии и изображений требуется доступ к этим ассетам в Roblox. GLB, Blender-файлы и исходные изображения включены для последующего переимпорта. При переносе под другого владельца проверьте доступность ассетов и при необходимости переимпортируйте их с обновлением манифестов.

Данные игроков находятся в Roblox DataStore (`GrowAMonster_v1`, `GrowAMonsterOwners_v1`). Их содержимое не экспортировалось и не сбрасывалось. Новый universe имеет отдельные сохранения. Секреты и API-ключи для сборки не требуются.

Исходная бинарная копия `.rbxl` сохранена без преобразования. Rojo 7.7.1 сообщает о неподдерживаемом новом свойстве `Terrain.VoxelGridAssetContentMap` при чтении: поэтому для точного восстановления настроек редактора используйте исходную копию плейса. Игровая земля и дорога строятся из Parts/MeshParts; все 702 шаблона ArtLib проверены после сборки.

## Загрузка в Git

Папка готова для нового репозитория. Удалённый репозиторий не создавался, отправка и публикация не выполнялись.

```sh
git init -b main
git add .
git commit -m "Snapshot Grow a Monster with Dealer V4"
```

Затем добавьте адрес вашего Git-репозитория и отправьте коммит. Git LFS для первого коммита не требуется: в этом экспорте нет файлов больше 100 МБ. Для дальнейшего хранения множества версий больших моделей можно отдельно настроить LFS.
