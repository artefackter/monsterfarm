# Мимик — оптимизированные копии моделей и иконок

Подготовлено 14 ноября 2026 года. Обработаны **14 моделей**: базовый мимик и
шесть костюмов, каждый в состояниях Idle / Aggressive, и **6 иконок**.
Согласованные исходники сохранены; их контрольные суммы проверены.
Это отдельный пакет для проверки. В игру, Studio, Rojo и `Icons.lua`
никакие изменения не внесены.

## Какой вариант выбирать

| Папка | Назначение |
| --- | --- |
| `models/` | Основной вариант: исходная геометрия и нормали, компактная запись GLB, два меша |
| `mobile/` | Дополнительный вариант с упрощением крупных поверхностей, требует проверки внешнего вида |
| `icons/ui512/` | PNG 512×512 для карточек, коллекции и обычных окон интерфейса |
| `icons/small256/` | PNG 256×256 для маленьких элементов интерфейса |
| `icons/large1024/` | PNG 1024×1024 для крупных портретов |

Для первой интеграции предпочтителен `models/` с подходящим размером PNG.
Модель и инструмент остаются двумя отдельными мешами; **все 37 костей**,
их имена, иерархия и bind-матрицы сохранены в обоих профилях.
У инструмента сохраняется собственная кость Biwa.
Одна иконка на костюм соответствует текущему устройству портретов игры.
Сами иконки ещё ожидают отдельного согласования владельца.

## Измерения

Итоги находятся в `summary.json`, подробности по каждому файлу — в `report.json`.
Размеры указаны для альтернативных экспортных наборов; исходные Blender-файлы,
исторические версии и обзорные рендеры не входят в эти суммы.
Наличие копий увеличивает размер рабочей папки; выигрыш относится к выбранному
набору файлов для будущей загрузки, а не к общему объёму репозитория.

Основной пакет: 14 исходных GLB **26,74 МБ → 20,78 МБ**, уменьшение **22,3%**.
Число мешей в наборе: **613 → 28**, по два на модель вместо 38–47.
Количество треугольников основного пакета не изменено — 171 234 на все 14 файлов.

Облегчённый пакет: **26,74 МБ → 17,92 МБ**, уменьшение **33,0%**.
Треугольников **171 234 → 143 852**, уменьшение **16,0%**.

Шесть PNG 1254×1254: **5,73 МБ → 1,20 МБ** для 512×512 (**−79,0%**),
**0,37 МБ** для 256×256 (**−93,5%**), **4,01 МБ** для 1024×1024 (**−30,0%**).
Рисунок не перегенерировался; уменьшены разрешение и размер PNG, удалены
необязательные метаданные. Прозрачность и композиция сохранены.
Число пикселей набора 512×512 примерно в шесть раз меньше исходного.

Это измерения локальных файлов и геометрии. Загрузка, память и FPS в Roblox
пока не замерялись. Roblox перекодирует загружаемые изображения: уменьшение
веса PNG само по себе не даёт такого же уменьшения памяти или времени загрузки;
для изображений значимо также разрешение.
[Рекомендации Roblox по производительности](https://create.roblox.com/docs/performance-optimization/improve).

## Что изменено

### Основные GLB

Все части персонажа объединены в `MimicBody`; `Biwa` и украшения инструмента —
в отдельный меш. Раздельные объекты Face, Hair, Finger и другие больше не нужны
для их движения: они двигаются соответствующими костями внутри общего меша.
Отдельные части и их диапазоны вершин перечислены в `report.json`.
Будущий игровой контроллер должен работать с костями; это не готовая замена
существующих процедурных Parts-ригов без адаптации.

Координаты и нормали остаются float32 без округления; триангуляция сохранена.
Цвета и веса записаны нормализованными 16-битными числами.
Погрешность их записи приведена в отчёте. Для этих типов достаточно стандартного
[glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html):
Draco, meshopt, KHR_mesh_quantization и внешние декодеры не используются.
Модели не содержат текстур или внешних зависимостей.

### Облегчённая геометрия

Упрощены крупные поверхности одежды, тела и волос. Вершины на стыках граней
соединены перед упрощением, чтобы не возникало разрывов; цветовые границы
сохраняются в атрибутах углов граней.
Лицо, глазницы, зубы, пальцы, кисти, инструмент, головные уборы и цветочный венок
не упрощались. Мелкие отдельные украшения и тонкие швы также защищены.
Количество треугольников каждого варианта и частей указано в `report.json`.
Оба состояния держат инструмент двумя руками.

При выборе `mobile/` нужно смотреть не только общий силуэт, но и крупные планы:
это дополнительный уровень детализации, а не побитовая копия одобренной геометрии.

## Проверка и сравнение

- `previews/Model_Comparison.png` — исходник, основной и облегчённый GLB рядом.
- `previews/All_Models_Idle.png`, `All_Models_Aggressive.png` — сравнения всех костюмов.
- `previews/Icon_Comparison.png` — один рисунок в исходном и уменьшенных размерах.
- `previews/original/`, `full/`, `mobile/` — рендеры из повторно импортированных GLB.
- `packing_validation.json` — проверка структуры, диапазонов, костей, матриц,
  точного сохранения геометрии и нормалей основного пакета, геометрии защищённых частей.
- `blender_validation.json` — повторный импорт 28 GLB; движение костей головы,
  челюсти, руки, пальца, волос, юбки и инструмента; обе точки хвата.
- `icon_validation.json` — различия рисунка на светлом и тёмном фоне при
  отображении в 64, 96 и 128 пикселях. Проверка RGBA и прозрачности выполнена при сборке.

Основные модели и исходники имеют разные схемы объектов. Нельзя напрямую
сравнивать количество Blender-объектов с реальными draw calls в Roblox;
результат рендеринга и загрузки потребуется замерить после разрешённой интеграции.

## Сборка

Требуются Python с NumPy/Pillow и Blender. Скрипты пишут только в эту папку.

```sh
python3 art/mimic-optimized-v1/build.py
blender -b --factory-startup --python-exit-code 1 --python art/mimic-optimized-v1/build_mobile.py
python3 art/mimic-optimized-v1/finalize_mobile.py
python3 art/mimic-optimized-v1/check_packing.py
blender -b --factory-startup --python-exit-code 1 --python art/mimic-optimized-v1/validate_blender.py
blender -b --factory-startup --python-exit-code 1 --python art/mimic-optimized-v1/render_comparison.py
python3 art/mimic-optimized-v1/compose_review.py
```

Промежуточные GLB в `intermediate/` нужны только для сборки и могут быть удалены
после проверки. По частям сохранены небольшие статистические JSON; полноценные
исходники остаются в `art/mimic-v2` и `art/mimic-forms-v1`.
Согласованные модели и оригинальные иконки не перезаписываются.
